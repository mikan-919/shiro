# 型はデータとして基質に置き、コロニーが提案し、当面は利用者が採用する

v0〜v2 の型はコードに書かれていたため、型を1つ足すたびにコードを書き換え、サーバーを再起動する必要があった。これでは改善のループがコロニーの中で閉じない。そこで v3 以降の型は、名前・欄・目的・読み手の義務を持つ型の提案を基質に追記し、採用されたものを参加者のプロンプトに渡す（2026-11-11）。v0〜v2 の型はコードのまま残す。

提案は、まだ読まれていない type-gap report が10件たまったときに、提案と評価の2回のモデル呼び出しで作る。評価（リプレイ）は過去のターンの再実行ではなく、report の「書きたかった状態」を提案の欄で書けるかの判定である。再実行は呼び出しが多く、ECO の要請に反するため採らなかった。

採用は、ADR 0002 の「リプレイによる採用」に当たるが、評価の判定が正しいかをまだ確かめていないため、当面は利用者の承認を経る。評価の判定と利用者の判断が何回か一致した後で、承認なしの採用に移るかを決め直す。
