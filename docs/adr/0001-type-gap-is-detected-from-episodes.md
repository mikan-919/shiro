# type-gap は自己申告に加えて、観察者がエピソードから検出する

当初は、参加者が表現に失敗したときに自分で type-gap report を残す想定だった。2026-11-10 の15ターンの実測で、共有ノート51件のうち自己申告は0件だった一方、タスク8件中7件が所有者や所有ファイルを本文の自由文に書いていた。歪めて書けてしまうので、書いた参加者には失敗に見えない。そこで、ターンの外からエピソードを読む観察者を置き、検出した type-gap を report として追記する。

観察者は誰にも命令せず、タスクも確保しないので、中央の指揮者を置かないという土台とは衝突しない。gist が1件も書かれなかったターンは読まず、費用はターンあたり最大1回のモデル呼び出しとする。report は1ターンにつき歪みの種類ごとに1件で、根拠の gist と出どころ（自己申告／検出）を必ず持つ。検出の正誤はその場では判定せず、型の提案をリプレイで評価する段階で根拠の gist に当て直して確かめる。

## Considered Options

- プロンプトで自己申告を強く促す: 参加者が歪みを失敗と認識していないので、促しても出どころが変わらない。全モデル呼び出しの入力も増える。
- 調整コストが発生したものだけを type-gap とする: コストが実測できたのは15ターンで1件だけで、繰り返し起きている歪みを拾えない。調整コストは未計測を許す欄にした。
